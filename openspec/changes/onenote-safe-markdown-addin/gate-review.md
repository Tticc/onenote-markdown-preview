# 第一阶段关卡审查——调整任务依赖关系的建议

**状态：用户已批准。** 获准开展第 2～5 阶段离线实现、构建和自动测试；并已批准进入安装阶段（见文末"安装授权"）。安装以 `HKCU` 单用户、`LoadBehavior=0`（手动加载）为限；`LoadBehavior=3` 自动加载仍未授权。

## 已获得证据的可行性

- 使用官方主互操作程序集（PIA）定义的 COM 接口，已通过无需注册的跨进程调用、原生功能区按钮回调，以及独立 COM 代理进程的激活和退出测试。
- 已在真实 OneNote 中完成手动加载测试插件、按钮回调、手动断开连接及测试代理进程退出。测试插件注册项已移除。
- 已检查正文选区内容与范围、相同文字在不同位置的区分、完整段落与段落结束位置的差异；已获得标题、混合对象、跨文本容器、跨单元格、多窗口和空选区的拒绝判断依据；已确认正文与搜索框焦点不同，以及 XML 可能保留旧正文选区。
- 已通过实际粘贴验证固定输出样例中的粗体、标题、列表、引用、斜体、删除线、任务符号和行内代码，并获得用户对显示效果及一次撤销的确认。行内代码样式已获接受。
- 用户已接受并实测默认等待 200 毫秒后恢复剪贴板的策略；独立 500 毫秒恢复测试、程序生成的文字/HTML/RTF/PNG/DIB 样本，以及真实 OneNote 常用内容快照测试均已有通过记录。其他进程复制新内容时，不覆盖新内容的测试已通过。
- 已通过离线剪贴板恢复协调测试，覆盖失败、占用、竞争、重复操作、执行顺序及资源边界。

以上证据只适用于实际验证过的样例和路径，不等于完整插件已经通过验收。

## 尚未解决，且不会免除的要求

- 正式集成后，仍需对比 OneNote 的启动性能和完整进程退出行为；此前观察到无弹窗但 OneNote 进程留在后台的情况。
- 仍需验证完整命令和快捷键的生命周期、真实 Markdown 解析器的安全性、取消操作、迟到结果、只读页面行为，以及点击功能区按钮后的焦点。
- 常用剪贴板内容的正式实现仍需验证：恢复失败后的处理、合并代理进程中的外部延迟渲染、隐私元数据，以及更多真实应用来源的兼容性。目前遇到记事本的未验证保护标记时仍会拒绝操作。
- 围栏代码块复制回文本后的空格保真尚未成立：RTF 显示效果获用户认可，但导出的文字未体现原始空格完整保留。在找到并验证严格保真的路径前，应拒绝围栏代码块；如果选区同时含有代码块与其他语法，必须整段跳过，不能只转换其他部分。
- 畸形或不支持的 Markdown 判定规则、支持语法的嵌套边界、解析器选型与实现尚未完成。固定输出样例通过，不等于解析器通过。

## 当前任务存在依赖循环

现有任务 1.8 要求：第一阶段所有测试通过之前，不得进入第 2～6 阶段。

但部分第一阶段验收需要真实的插件、解析器和启用/禁用协调逻辑，而这些组件安排在第 2～5 阶段实现。

因此形成循环：

```text
第一阶段全部通过，才允许实现完整插件
                  ↑
                  │
部分第一阶段测试，需要完整插件才能执行
```

继续增加固定输出探针无法证明完整集成行为，反复让用户手动准备样例也不能消除这一依赖。

## 建议调整方案——待用户批准

1. **保留全部现有证据，不提前勾选未完成任务。** 将范围过大的任务拆分为“已验证的前置证据”和“待完成的集成验收”，而不是直接标记整项通过。
2. **允许开展第 2～5 阶段的离线实现、构建与自动测试。** 仅实现已明确支持的安全子集；不自动注册 COM 插件、不设置随 OneNote 启动加载，也不写入真实笔记。
3. **把上述未解决问题保留为安装、发布前的阻塞条件。** 正式实现遇到未支持的围栏代码块、未知或未验证的保护类剪贴板格式、无法确认的选区范围时，必须拒绝操作。这沿用用户已批准的失败即跳过规则，不代表允许静默丢失内容或修改空白字符。
4. **准备一次完整的预览交付。** 包括预览构建、自检工具、一套准备好的测试页面或文本材料，以及统一反馈表。
5. **自动测试通过后，只安排一次集中人工验收。** 正式安装或分发前，仍必须通过真实宿主加载、启用/禁用、快捷键、只读页面、剪贴板恢复及实际输入样例等验收。若发现新问题，针对问题修复和复测，不重复无关且已通过的样例。
6. **不把强制结束宿主进程作为常规测试步骤。** 保留此前明确的异常恢复规则，不宣称绝对安全，也不将预览版称为完整交付。

## 另一种选择

保持原来的严格阶段关卡，只继续探针调查。但在调整依赖之前，无法验证需要真实解析器和完整插件才能执行的集成行为。
